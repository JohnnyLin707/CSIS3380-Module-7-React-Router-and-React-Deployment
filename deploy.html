免费部署指南

依据《Deploying your Apps for Free》整理：Render、Vercel、Netlify、GitHub Pages 四大平台的部署流程，以及使用 React Router 的应用必须解决的「刷新 404」问题。

🏗️部署前 · 生产构建

把 React 应用部署到生产服务器前，需要先生成生产就绪的构建：

terminal
npm run build

该命令会在项目里生成 build（Create React App）或 dist（Vite）文件夹，里面是全部静态文件：

  • 把所有 JS 打包压缩成一个（或少数几个）文件，并压缩 HTML 模板与 CSS，减少下载时间；
  • 提供 service worker 文件，支持离线运行；
  • 这个文件夹就是要部署到服务器的内容。

想在本地验证生产构建，可以用 serve：

terminal
npx serve -s build        # CRA 项目
npx serve -s dist         # Vite 项目

⚠️核心问题 为什么刷新子路由会 404

使用 React Router 的 SPA 只有一个真实的 HTML 文件（index.html）。当你访问 https://myapp.com/about 时：

  • 开发服务器（npm run dev）会把所有路径都返回 index.html，所以没问题；
  • 但静态服务器默认去磁盘上找 /about 这个文件 —— 找不到，于是返回 404！
🎯

解决方案（二选一）：

1. 告诉服务器「所有路径都返回 index.html」（重写规则）—— 适用于 Vercel、Netlify、Render 等；

2. 使用 HashRouter（URL 形如 /#/about）—— 服务器只看到 /，天然不会 404，适合 GitHub Pages 这类无法配置的服务器。

对比 BrowserRouter：https://app.com//dashboard ← 干净，但服务器需配置重写 HashRouter： https://app.com/#/dashboard ← 带 #，但任何静态服务器都能用

1Render.com

  1. 把代码仓库推送到 GitHub；
  2. 打开 render.com，创建新项目，选择 Web Service，并选中 GitHub 仓库；
  3. 填写表单，特别注意 Build Command 与 Start Command 要用对：
字段静态站点（Vite）Node/Express 服务
Build Commandnpm install && npm run buildnpm install
Publish / StartPublish directory: distStart command: node server.js
⚠️

Render 的 Static Site 默认会处理 SPA 重定向；如果你部署的是自己写的 Express 服务，需要在服务端把所有未知路径都返回 index.html。

2Vercel

流程与 Render 类似：从 GitHub 导入仓库即可。Vercel 提供免费套餐，整体体验通常比 Render 更好。

但使用 React Router 的应用，经常需要添加 vercel.json，确保刷新页面时路由依然有效。

Vercel 自动检测的框架（默认内容）

vercel.jsonJSON
{
  "routes": [
    {
      "src": "/(.*)",
      "dest": "/"
    }
  ]
}

含义：所有请求（/(.*) 匹配任意路径）都交给 /（即 index.html）处理，React Router 再在浏览器端决定渲染哪个页面。

Vercel 无法自动检测的平台（如 Express 应用）

vercel.json（Express 应用）JSON
{
  "version": 2,
  "builds": [
    {
      "src": "server.js",
      "use": "@vercel/node"
    }
  ],
  "routes": [
    {
      "src": "/(.*)",
      "dest": "server.js"
    }
  ]
}

如果启动文件是 index，则把 "src" 写成 "index.js" 或 "./index.js"。

3Netlify

Netlify 同样简单，甚至可以直接把文件夹拖拽上传（不一定需要 GitHub 仓库）。但对于使用 React Router 的应用，需要在 public 文件夹中添加 _redirects 文件：

public/_redirectsTEXT
/* /index.html 200

含义：任何路径（/*）都返回 index.html，状态码 200（不是 301/302 重定向，避免浏览器地址被改写）。这样刷新 /dashboard 时服务器也会返回应用入口，路由正常恢复。

4GitHub Pages / 生产服务器

先执行 npm run build 生成构建产物（见本章开头），然后：

1. 在 package.json 中添加 homepage

package.jsonJSON
"homepage": "https://<username>.github.io/<repository-name>"

2. 安装 gh-pages 并添加脚本

terminal
npm i gh-pages
package.jsonJSON
"scripts": {
  "predeploy": "npm run build",
  "deploy": "gh-pages -d build"
}

3. 推送代码并部署

terminal
git remote add origin https://github.com/<username>/<repository-name>.git
npm run deploy

新构建会发布到 gh-pages 分支，稍后即可通过 https://<username>.github.io/<repository-name> 访问。

⚠️

重点：如果应用使用 React Router，推送部署前把 <BrowserRouter> 改成 <HashRouter>，否则部署后会丢失路由页面（GitHub Pages 无法配置重写规则，刷新子路由必然 404）。

💡

本站的在线演示正是因此使用了 HashRouter：这样你双击本地 HTML 文件（没有服务器）也能完整体验所有路由功能。

☑️部署检查清单

  • 本地 npm run build 无错误，产物为 dist/（Vite）或 build/（CRA）；
  • 用 npx serve -s dist 本地验证生产构建，各路由正常；
  • 构建命令与发布目录在平台表单中填写正确；
  • 按平台要求配置重写规则（vercel.json / _redirects），或改用 HashRouter；
  • 部署后在线上直接访问并刷新一个子路由（如 /dashboard），确认不是 404；
  • GitHub Pages 项目确认 package.json 的 homepage 与仓库地址一致。
